⑤ 上線docs.moonland.ai 更新
  1. 確認內容：只有已公開的頁面會進靜態版（草稿、封存不會）。先在公司網站的說明中心看一遍。
  2. 開終端機：檔案總管打開 U:\_研發\tznung\moonland-docs\repo，在網址列輸入 powershell 按 Enter。
  3. 打包（先不推送）：輸入下面這行按 Enter。最後出現「完成」和檔案數、大小就好了；有新影片時要等幾分鐘。 node tools/build-static.js
  4. 預覽：輸入下面這行，用瀏覽器打開 http://localhost:8091 看改過的頁面，看完回終端機按 Ctrl + C。 python -m http.server 8091 -d ..\moonland-docs-site
  5. 推送：沒問題就輸入下面這行。出現「已推送」就完成；出現「內容和上次一樣」表示沒有新內容，不會推送。 node tools/build-static.js --push
  6. 確認上線：用手機或公司外的網路打開 docs.moonland.ai。公司電腦連不到外部網址時，不代表網站壞了。

B. 改了程式：先推公司網站

程式改好、在 repo 資料夾的終端機輸入（每行按一次 Enter）：

node server/test.js git add -A git commit -m "這次改了什麼（用一句話寫）" git push gitea main git push origin main
  • node server/test.js 最後沒有出現錯誤才繼續；有錯誤時不要推，公司網站的自動部署也會因為同樣的錯誤失敗。
  • git push gitea main 會自動部署公司網站，約 5～10 分鐘。部署好、在公司網站確認新功能正常後，再照 A 打包推送到 docs.moonland.ai。
  • 改了 css 或 js，要把 index.html、edit.html、admin.html 裡的 ?v= 版本號換掉，否則讀者會看到瀏覽器快取的舊檔。

遇到狀況

畫面出現怎麼辦
⚠ 發現公司網址，停止打包有文章貼了 moonshine-studio.net 等公司網址。照畫面列出的頁面，到後台拿掉網址、儲存，再打包一次。對外網站絕不能出現公司網址。
⚠ 找不到要拿掉的段落有人改了「點數 3D 模型」介紹 3D 範例的文字。網站還是能用，請負責程式的人更新 tools/build-static.js 的 STATIC_EDITS。
找不到 ffmpeg新影片和音樂會用原檔，網站一樣能用，只是比較大。
讀取內容失敗要在公司網路裡、公司說明中心打得開才能打包。
dubious ownership、unsafe repository資料夾在共用槽，Git 不認得擁有者。照下面「第一次在新電腦使用」第 3 步加一次就好。
推送失敗：403、Permission denied登入的 GitHub 帳號沒有寫入權限：靜態版找 MoonShineVFX 的管理員、程式 repo 找 r-ty-m1 的擁有者加權限。推 gitea 出現 403 或 authentication failed：照公司 mason 的 gitea-access 設定個人 access token。
推送失敗：rejected、fetch first有人先推了新的內容。不要強制推送。程式 repo 先輸入 git pull gitea main 再推；靜態版請負責程式的人處理。

第一次在新電腦使用（同事接手時）

  1. 安裝：Node.js（LTS 版）、Git、Python。裝好後重開終端機，輸入 node -v、git --version、python --version 都有出現版本號就好。
  2. 權限（找管理員加）：
    • GitHub MoonShineVFX/moonland-docs-site 的寫入權限（推靜態版，A 需要）
    • GitHub r-ty-m1/moonland-docs 的寫入權限，與公司 Gitea ufst47/moonland-docs 的寫入權限（改程式，B 才需要）
  3. 讓 Git 信任共用資料夾（每台電腦做一次）： git config --global --add safe.directory U:/_研發/tznung/moonland-docs/repo git config --global --add safe.directory U:/_研發/tznung/moonland-docs/moonland-docs-site
  4. 第一次推送時會跳出 GitHub 登入視窗：用有權限的自己的帳號登入。不要用別人的帳號或把密碼、token 貼給別人。
